# سجل القرارات المعمارية

## D001 — Python هو القلب
السبب: تكامل قوي مع الملفات، المتصفح، العمليات المحلية، التحليل، الاختبارات ووكلاء الذكاء الاصطناعي.

## D002 — Playwright هو محرك المتصفح الأساسي
السبب: إدارة تابات وجلسات وتنزيلات وتتبع موثوق، مع إمكانية تشغيل خلفي.

## D003 — لا نعتمد على DOM فقط
السبب: بعض الأنظمة قد تكون مرسومة أو غير قابلة للقراءة كعناصر عادية. لذلك يوجد Vision fallback.

## D004 — Network قبل UI
إذا أمكن الحصول على التقرير من طلب شبكة مصرح به بنفس جلسة المستخدم، فهو أفضل من محاكاة عشرات الضغطات.

## D005 — لا إحداثيات مطلقة
بسبب اختلاف دقات الشاشات. نستخدم عناصر دلالية أو إحداثيات نسبية.

## D006 — SQLite للتشغيل وDuckDB/Parquet للتحليل
نفصل سجل العمليات عن تاريخ البيانات التحليلي.

## D007 — الويب آب هو الواجهة الرئيسية
المستخدم النهائي لا يحتاج التعامل مع ملفات الكود أو الطرفية.

## D008 — Codex وClaude Workers خلفيون
يتم تشغيلهما من Agent Manager مع صلاحيات وسياق وسجل واضح.

## D009 — التصعيد تدريجي
حل ثابت ثم وكيل أقل تكلفة ثم نموذج أقوى ثم تدخل بشري.

## D010 — الإصلاح الذاتي Test-First
لا يُنشر Patch لمجرد أن الوكيل اقترحه. يلزم Sandbox واختبارات وتراجع.

## D011 — Camoufox ليس أساس النظام
يمكن اختباره لحالات خاصة، لكن النواة لا تعتمد عليه.

## D012 — المستودع العام لا يحمل سياقًا داخليًا حساسًا
أي مواد داخلية كاملة تنتظر مستودعًا خاصًا أو مخزن معرفة آمنًا.
